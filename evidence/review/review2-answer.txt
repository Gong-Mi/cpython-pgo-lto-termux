 - 覆盖率明显不足，且缺口有方向性。现在这 7                                     
 个（循环/调用/列表/字符串编解码/JSON/正则/dict）覆盖的是「语言级热点操作」，缺 
 ：异常处理、属性/方法访问与类机制、生成器/迭代器/推导式、f-string              
 与格式化、闭包与作用域、函数参数与 kwargs、内存分配与                          
 GC、解释器启动时间、线程/GIL、以及任何多模块真实程序的混合比例。               
 - 更关键的是形态偏差：timeit                                                   
 把同一个操作塞进紧循环，这是分支预测最友好、I-cache 最友好、也最容易被 PGO     
 的代码布局/冷热分离收益放大的形态。真实 Python                                 
 程序分支多、调用图深、路径混合，PGO                                            
 的收益通常显著小于这类紧循环。因此这组数字更应被当作 PGO/LTO                   
 效应的上界，而不是典型值。                                                     
 - 还有一个隐藏的「测什么」问题：JSON、正则、字符串编解码基本在 C               
 扩展里执行，它们衡量的是 C 扩展的构建，而不是 Python 解释器循环的性能。把 7    
 个用例等权合并成一个数，会把这个成分混进去。                                   
 - 另外只测单进程单线程单核，因此不能推论任何并发、异步、多进程、网络或 IO      
 场景。                                                                         
 - 诚实的边界写法（可直接采用的模板）：「在与 Termux 官方 Python                
 3.14.6（构建选项 X）对比、core 5、单进程单线程、7 个纯 CPU                     
 紧循环微基准、无磁盘与网络 IO、存在间歇第三方负载的条件下，自构建 PGO+thin LTO 
 版本的 7 用例配对比值中位数为 （95% CI ），且 7/7 用例方向一致。该数值表示     
 PGO/LTO 在 CPU-bound 紧循环形态下的解释器循环收益上界；不适用于                
 numpy/科学计算、字符串与 IO                                                    
 密集服务、多线程/多进程、解释器启动、以及任何具体应用的整体加速比。噪声底为    
 __%，观测效应__其外/其内。」——最后一句是结论能否成立的总开关。                 
                                                                                
 按性价比排序的最低成本改进（建议只做前四条）                                   
                                                                                
 1) 每个二进制加一轮丢弃预热，并把顺序改成 ABBA 或随机化；同时跑一次 A-vs-A     
 安慰剂作为噪声底与位置效应标尺。这一条最便宜，直接决定后面的数字可不可信。     
 2) 统计上改为「先算每轮配对比值 r_i，再取中位数 + bootstrap                    
 CI」，并预注册尖峰剔除规则、双报结果。成本几乎为零。                           
 3) 改用进程 CPU 时间（process_time/ru_utime）作为主指标，墙钟作为辅证；5       
 次重复改报 min/median/mean 三个值。                                            
 4) 补一行构建选项 diff 与 C 扩展来源核对，以及每轮 fault/RSS、core 5           
 频率与温度记录。若发现扩展来源不一致，整个结论需要重做而不是修补。             
                                                                                
 做完 1-3 条，若 CI 下界仍明显大于 1.0 且 6-7 个用例同向，则「B 比 A            
 快」成立但仅在「core 5 上的解释器紧循环」范围内；若 CI 跨过                    
 1.0，正确结论是「在本文噪声分辨力下未观察到显著差异」，而不是「B 更快」。
